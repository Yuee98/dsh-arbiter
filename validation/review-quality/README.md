# 完整评测报告归档

本目录保存经过实际运行并明确说明适用范围的 Markdown 报告及必要组明细。当前没有经本阶段实际运行授权产生的正式模型评测条目；工程 fixture 的通过不登记为模型质量通过，也不生成虚构版本或成绩。

真实报告按 `releases/<被测版本>/<实际评测ID>/report.md` 放置，必要明细在同前缀的 `.details/`；主报告链接全部 split/业务组。这里以简短列表维护版本、run ID、状态和主 MD 的相对链接，不另建 manifest、自动“最新通过”状态或发布服务。新增条目必须对应实际生成并已提交的文件；失败和证据不足的运行同样保留，不挑选最好一次替代其他结果。

已有授权的有界运行可以使用 `run <计划> --report --out <报告前缀>`，已有工件可以用 `report <运行目录> --out <报告前缀>` 离线生成。具体参数、失败行为与保护见 [默认完整报告与归档](../../evals/README.md#默认完整报告与归档)。这两种输出复用同一报告核心，不因缺结果自动发起请求。

Git 默认提交主 `.md` 与 `.details/` 必要明细；JSON、HTML 和原始 plan/index/records 可作为实际可访问的运行附件。提交前检查主 MD 的所有组明细链接。`.local` 或临时绝对路径只是本机副本，不能作为 GitHub 上可访问附件的证明；附件未归档时如实保留 local-only 说明，不伪造 URL，也不复制一份源数据、配置或独立审计清单。

开头的被测 commit、dirty、输入配置/范围和原运行位置来自保存的运行证据。报告文件后来进入 Git 的 commit 是另一事实，由其 Git 历史定位；不把提交报告时的 HEAD 填成被测版本。旧工件没有被测来源时为 unknown。仅展示代码变化可根据实际 diff 说明复用；模型、prompt、输入或预算变化需要新运行证据，不能靠重算和换参考掩盖缺口。

报告生成成功不表示运行完整或模型质量通过。索引与记录矛盾、技术失败、未完成及缺参考仍显示在完整计划中。正式验收线、参考资格或对应证据未确定时保持未评估；费用未知不填零。本说明不授予真实模型、付费资源、日常日志访问或人工标注授权；报告与代码/文档按现有 PR 流程分别提交，不自动进行 Git 操作。
