# 旧测试数据重置工具（RQ-07）

旧审计结构在本版被**拒绝**而不是迁移：库的结构版本不是当前版本时，插件在建立任何连接之前就拒绝打开该文件，健康视图给出「需重置」的原因，文件按字节保持原样。本文说明那个「重置」动作本身：一个限定范围、可核对、单次执行的操作工具。

真实删除属于独立操作任务（RQ-18），不在本工具的开发交付中执行。

## 1. 它做什么、不做什么

| | 内容 |
|---|---|
| 作用范围 | **一个** DSH 数据目录下的 `arbiter/` 子目录，且只处理这个插件自己的文件 |
| 目标文件 | `arbiter.db`、`arbiter.db-wal`、`arbiter.db-shm`、`arbiter.db-journal`、`arbiter.db.backup-v<数字>`、`arbiter.db.backup-v<数字>.staging`，以及任何备份／残留文件同名的 `-wal`／`-shm`／`-journal` 边车 |
| 删除条件 | 该文件被证明是**本插件写的旧结构**审计库，或它的迁移备份／残留 |
| 不删除 | 当前结构的审计库（新记录）、更新版本写的库、其他插件的数据库、其他 profile 的恢复副本、宿主会话日志 |
| 触发方式 | 只由操作者显式运行；不进入启动、安装钩子或 CI |

工具**不**通过文件名推断身份：`arbiter.db` 这个名字在别的插件里也可能出现。删除前会读文件头确认它是 SQLite、读出结构版本，并检查 `calls`／`stages`／`model_calls`／`config_snapshots` 四张表是否齐全。任一项不成立时该文件被标为 **REFUSE**，整次运行被阻止——宁可不删，也不猜。

## 2. 默认 dry-run

```
pnpm reset:test-data --home ~/.dsh
```

不加 `--apply` 时**不删除任何东西**，只打印清单：目标、动作、字节数、行数、表名、文件摘要，以及每个决定的原因。清单包含：

- **数据目录与插件目录**的绝对路径；
- **目标清单**：`DELETE`／`KEEP`／`REFUSE` 三种动作与对应原因；
- **数量**：文件数、字节数、记录数、保留文件数；
- **profile 与项目**：被删数据里出现的 profile 名与 workspace，各自记录数；
- **排除项**：本工具明确不处理的宿主会话日志、`last-good` 恢复副本、其他 profile 与插件；
- **拒绝原因**：任何 `REFUSE` 都列在这里，并阻止应用；
- **`plan id`**：目标集合的摘要，应用时必须回传。

dry-run 同样不修改被检查的文件：结构读取在一份临时副本上完成，副本用完即删。打开原文件（即使只读）会让 SQLite 恢复 WAL、checkpoint 并删除 `-wal`／`-shm`，那样「预览不改动」就是假话。

## 3. 显式执行

```
pnpm reset:test-data --home ~/.dsh --apply <上一步打印的 plan id>
```

执行前工具会重新核对：

1. 计划里没有 `REFUSE`；
2. 计划里确实有要删除的文件；
3. 回传的 `plan id` 与当前计划一致——**文件在预览之后变过**（大小或内容摘要不同）时，摘要必然不同，运行在删除第一个文件之前就停下。

删除按计划顺序逐项进行，遇到失败立即停止并报告已经删掉的文件、字节数与记录数，让部分完成的状态可以核对，而不是只报一个失败。

## 4. 安全边界

| 情况 | 结果 |
|---|---|
| 目标不存在 | 不删除，报告「暂无旧数据」 |
| 当前结构的库 | `KEEP`，并说明新记录会保留 |
| 更新的结构版本 | `KEEP`，不改不删 |
| 非 SQLite 文件占用了该名字 | `REFUSE`，整次运行被阻止 |
| SQLite 文件但不是本插件的表 | `REFUSE`，整次运行被阻止 |
| `arbiter.db` 是符号链接 | `REFUSE`：删掉名字不等于删掉操作者被告知的那份数据 |
| `arbiter/` 目录本身是链接 | `REFUSE`：作用范围可能落在数据目录之外 |
| 传入的是 profile 目录 | `REFUSE`：避免把「作用范围选错」读成「旧数据已经没了」 |
| 有孤儿 `-wal`／`-shm` 但库不存在 | `KEEP`：无法证明它属于本插件 |
| 结构旧但**同时**有当前记录格式的行（混合状态） | `REFUSE`，没有放宽开关 |
| 没有 `record_format_version` 列（本插件首版结构） | `DELETE`（可删）：这些行不声明任何记录格式，因此不算当前格式数据 |
| 有表无法计数 | `REFUSE`：影响清单不完整时不能删 |
| 插件目录是指向不存在位置的符号链接 | `REFUSE`：「不存在」与「存在但无法核实」必须分开 |
| `calls` 表没有 `profile` 列 | `REFUSE`：无法归属的 profile 不能通过授权名单 |
| 目录存在却无法列出（权限等） | `REFUSE`：不是「没有旧数据」，而是没看见 |
| 空 SQLite 文件（无应用表） | `REFUSE`：没有表既可能是残留，也可能是别的工具，名字不是证据 |
| `.staging` 不是可读的本插件旧结构副本 | `REFUSE`：只有文件名不足以证明它属于本项目 |
| 主文件头版本与 WAL 中生效版本不一致 | `REFUSE`：两个读数有一个是错的，工具不替人选择 |
| 有未授权的 profile 记录 | 加 `--profiles a,b` 时，未列出的 profile（或无法归属的记录）阻止整次运行 |

混合状态那一条是设计要求的直接体现：结构旧的库里可能已经有临时构建按**当前**记录格式写入的行，无差别清空会把当前契约产生的数据一起丢掉。这里**没有**放宽开关——本工具的授权范围是「旧测试数据」，不是「当前契约产生的记录」。需要丢弃后者是另一个决定，不能由本工具的一个命令行参数代替。真要回收这份混合库，先单独确认那些行的归属，再走对应的操作任务。

`--profiles` 的作用同理：审计库按数据目录共享，一个旧库可能同时存着几个 DSH profile 的记录；只有被点名授权的 profile 才允许被清空。一个**无法归属** profile 的 `calls` 表按拒绝处理——「没找到别的 profile」不等于「别的 profile 不受影响」。

几个「读不出来」的边界同样按拒绝处理，因为把读失败当成读成功是这个工具最危险的失败方式：目录列不出来、副本读不出来、版本读数互相矛盾、`.staging` 文件读不出来，都会阻止整次运行，而不是产出一份看起来很干净的清单。

`calls` 缺少 `record_format_version` 列是**首版结构**的事实，不是读取失败：这些行没有声明记录格式，因此全部属于旧数据，工具照常把它们计入并删除。把「没有这一列」当成「数量读不出来」会让工具拒绝它本来就是要清理的那批库，这是实测到的真实缺陷。

`.staging` 残留有个实际取向：`VACUUM INTO` 被打断的产物通常是**截断的、读不出来的**，而名字本身不是证据。因此只有「可读 + 带本插件四张表 + 结构已退役」的残留才会被删除，其余一律拒绝并留给人工。这会留下一个偶发的手工清理步骤，换来的是这一类别不会因为一个文件名而误删别人的数据。

## 5. 重复运行

删完之后目录里只剩不相关的文件（例如 `last-good/` 与操作者自己的笔记）。再跑一次时：

- 数据库不存在 → `KEEP`，`files: 0`；
- 计划没有可确认的目标，因此 `--apply` 直接返回「没有要删除的内容」。

插件下次启动会按当前结构新建空库。**新记录不进入删除范围**，所以第二次运行不会清掉重置后写入的数据；旧记录也不会回灌——本版没有迁移链，也就没有回灌路径。

## 6. 报告与证据

每次运行输出同一份结构：先是计划，再（真实执行时）追加一段执行结果：

```
Execution:
  result: removed
  files removed: 2
  bytes removed: 81,920
  records removed: 4
  - arbiter.db [database]: 40,960 B, 2 row(s), sha256 a1bce2…
  - arbiter.db.backup-v2 [backup]: 40,960 B, 2 row(s), sha256 a1bce2…
  left in the directory: last-good, notes.txt
```

RQ-18 的前后清单、执行命令、数量与新库验证证据由该任务保存到 `validation/review-quality/reset/`；本工具只负责让这些数字可复现。

## 7. 测试如何证明它不误删

`tests/integration/reset-test-data.test.ts` 全部在 `mkdtemp` 建立的临时数据目录中运行，覆盖：

- dry-run 后整棵目录树的**摘要与文件列表都不变**（对真实 `~/.dsh/arbiter/` 也做过同样的逐字节核对，见 PR 正文）；
- 显式执行只删四类目标（旧库、两个备份、可读的 `.staging` 残留），`other.db`、`notes.txt`、`last-good/`、其他插件目录逐字节保留；
- 部分失败时报告标为 `PARTIAL`，不写成「nothing removed」；
- 备份的 `-wal`／`-shm` 随备份一起删除，且只改 WAL 后 `plan id` 会变化、旧 token 被拒绝；
- 可读的 `.staging` 残留把行数带进预览与执行记录；
- 重复运行不删新记录；
- 回传错误的 `plan id`、或用另一个数据目录的 `plan id` 都不删任何东西；
- 预览后文件内容变化、目标文件被换成符号链接、整个目录被换成符号链接时拒绝执行；
- 主文件头版本与 WAL 生效版本不一致时拒绝；
- 首版结构（无 `record_format_version` 列）可正常重置，且行数进入执行记录；
- 需要引号的表名（如 `operator notes`）被正常计数，不因名字被跳过；
- 插件目录是指向不存在位置的符号链接时拒绝，而不是报「空作用域」；
- `calls` 缺 `profile` 列、目录无法列出、空 SQLite 文件、不可读或当前结构的 `.staging` 全部拒绝；
- 非本插件库、更新版本库、非 SQLite 文件、符号链接、profile 目录、未授权 profile、混合记录格式全部拒绝，且文件摘要不变；
- 会话日志被报告为排除项，永不进入目标清单。

## 8. 未解决事项

- 本工具只处理审计库与迁移备份。宿主会话日志里的 `plugin:arbiter/*` 记录**不删除**：一份日志包含整段对话与其他插件，改写它需要宿主公开的删除接口，本版没有该接口。RQ-18 只按清单删除确认属于本项目的文件。
- 被截断的 `.staging` 残留（`VACUUM INTO` 被打断的常见产物）会因不可读而被拒绝，需要人工确认后单独删除。这是刻意取舍：这一类别除文件名外没有可核对的证据。
- 混有当前记录格式行的旧库会一直被拒绝，直到那些行的归属单独确认。本工具不提供绕过。
- 该工具写入 `package.json` 的一个 script，不改变 `verify` 流程，也不进入任何自动启动路径。
