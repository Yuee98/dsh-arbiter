# 新阶段任务拆分与交接

状态：2026-11-01 issue 图发布依据。关联[主方案](complex-workflow-evals.md)、[数据方案](complex-workflow-evals-data.md)、[Prompt 说明](complex-workflow-evals-prompt.md)和[工作流目录](complex-workflow-evals-workflows.md)。用户已授权创建 GitHub milestone 和 parent，并将以下工作包细化为独立验收的执行 issues；实际编号、关系和发布记录以 GitHub parent 为准。

原 19 个交付单元合并为 **8 个工作包**。CW 编号保留作已有讨论的索引，表中的旧编号并入同一工作包，不再各建一个 issue 或审批窗口。一个工作包可分多个小 PR；代码和文档仍按项目约定分开提交。数据规模、5:3:2、连续任务、首版工具结果类型、已确认的 prompt 规则和动态模型共识门槛保持。

## 2. 各工作包的完成条件

### CW-02 数据格式与旧集迁移

接收 dsh 的实际 commit 和相关配置，确认旧阶段修复及已知限制；不另写一份重复基线规格。数据按 split → 业务组组织，核心为 workflows/cases、labels、opinions 集合，复杂案例的作者说明可选。目录和约定文件名决定加载范围，不增加 manifest 或逐层 hash。

工作流保存真实有序的消息/调用/结果及必要关联，审查点保存截止点和待审动作。沿用宿主事件形态与共享构建器，用薄适配器转换，不开发通用场景语言、事件树解释器或业务执行引擎。普通根默认以自身 root ID 作为 lineage，只有实际派生关系才显式合簇；主视图按运行生成，不逐点手工维护独立视图文件。

将旧 51 条的 13/22/16 分组迁入 legacy-v1，同步加载、检查、标注导入/导出和报告定位。验证 51/49、16 个 family、原 ID/输入/标签/模型意见和历史结果等价；旧字段按原义读取，不回写历史。旧格式保留最小只读适配，新格式作为唯一编辑源。

验收重点：事件顺序及 call/ask/session 关联、截止点与未来信息排除、重复 ID、同源不跨 split、按请求范围加载，以及导入不覆盖其他人的修改。文件重排或格式化不改变记录 ID；实际材料变化须复核标签。稳定 ID、Git 历史和实际输入比较足以支持这些检查。

### CW-18 工具结果采集与存储

复用宿主事件和现有审计存储，覆盖可观测的前置查询等未触发 reviewer 的调用。保存实际得到的正文、来源、状态和截断信息；结果只能在执行后追加，不回填执行前审查视图。

落实已确认的文本/可序列化结构化结果范围、共同凭据脱敏、单次调用正文合计 1 MiB、超过 64 KiB 转文件及统一 retention。细则以主方案 §2.3/§2.5 为准；媒体只记录类型/引用/正文未提供。日志文件缺失或已清理须如实表达。

在现有存储上完成读写、恢复和清理；不另外建立内容寻址仓库、去重服务或导出平台。只有现有共享引用确实存在时才处理对应回收关系，不为假设的共享场景先造一套机制。

验收覆盖多通道合计、空/失败/未提供结果、上游及本地截断、脱敏后持久化与送审、重启、文件缺失、落盘失败及统一容量清理。采用临时 SQLite/文件和适用的隔离宿主测试。

### CW-07 统一生产输入与回放

直接实现一套可被生产与评测共同调用的材料构建路径。落实 Prompt 说明中的统一时间线、父人类证据、明确问答绑定、机械保位、T/H/C、配置迁移及截断；不单做 eval 原型后再重写生产接线。设置和宿主接线随功能完成，S2 后只调整实际需要的参数或措辞。

保留用户已确认的约束：无 prompt 前置字符/20／5／40 条数/固定最近 N 轮限制；普通 assistant 和 checkpoint 的单候选规则；两类最新人类原文及明确绑定问题保位；工具结果为普通工具来源；父子各自有序，当前动作及未来结果不进入历史。

先复用已有读取和缓存，有界读取及缺失状态必须正确。新索引、分页优化或额外缓存层只在宿主接口或实测性能确有需要时添加，不要求全部建设。必要缺口、来源和省略说明送 reviewer；扫描量、预算运算、缓存统计等诊断留运行记录。

主数据采用固定轨迹逐点投影。本次模型答案不回填后续历史。真实宿主续行以少量参数化集成/E2E 用例验证批准、拒绝、无回复、迟到回复、重启及父消息刷新，不要求为每个数据根搭建可执行业务沙箱。

验收按 Prompt 说明的行为契约覆盖边界：正常与硬预算降级、保护原文无法容纳、取消旧限制、跨轮/父子来源、晚到结果、重复材料、冷恢复等价和 source 缺失。确保实际生产与 eval 输入一致；宿主改变运行隔离 DSH E2E。

### CW-04 标注与参考选择

用户已确认在本工作包增加轻量本地标注页，替代此前“首版只用 JSON/Markdown”的限制。页面按工作流/审查点组织当前可见材料、裁决表单、量表和可展开模型意见，支持分歧/待标筛选、自动草稿、确认后写回标签、快捷键和断点续标。已确认的页面设计见数据方案 §4.1，尚未实现；现有 JSON 导出/导入保留作批次交换，页面复用同一校验与写入逻辑。

主要人工任务是裁决 R/A、独立期望行为并给简短依据。基线矩阵行为由程序计算；来源、时序、预算和 M0 等工程断言放既有测试，普通题不再人工填写完整工程状态卡。材料不足或人类明确争议仍保留对应状态。

保存所有实际取得的独立模型意见、缺答和失败；按数据方案使用人工优先和模型共识 fallback。用户已确认 `K>=3 AND (K/N>=80% OR K>=N-1)`，不固定 N；剩余意见的 R/A 各最多偏差一档，独立期望行为全体一致；跨 A1 或关键证据冲突转人工，缺答不缩 N，补齐前不自动采用。模型参考与人工确认分别统计，新增意见重新计算，不能删除异议凑通过。

标签复用首版只处理相同实际视图或人工明确确认的等价案例，不建立通用语义等价推断/继承规则引擎。变更由 Git 留痕，批次保留源 commit/配置和材料；导入按 ID 更新并检查相关记录冲突。

验收覆盖导出—裁决—导入往返、人工优先、共识的票数/一档偏差/行为/禁止冲突/缺答边界、输入变更复核和旧运行参考保留。本地标注页增加草稿刷新/重启恢复、确认写回与保存失败、冲突、模型意见显隐、未来信息隔离和内容转义测试；独立盲标不加载意见，辅助审阅允许主动展开。草稿保存不冒充人工确认，不自动批量确认未审阅题目或提交 Git。页面仅更新所选数据集的标签/草稿，不另建标签数据库、托管账号或多人协作平台。人工范围与正式用途仍待确认，按数据方案 §4.1 的建议准备首批全审、随机根抽检和关键/争议复核入口；网页交付不自动授予机器参考正式验收资格。

### CW-19 指标、矩阵回放与报告 CLI

复用现有 `pnpm evals report/replay` 和统一报告对象，指标、分类、比较与三种输出放在一个工作包，避免先造通用统计平台再接渲染器。

首版核心：覆盖/失败/未标、参考来源、行为混淆与误放/误拒/不必要人工、R/A 配对及偏差、按 target/split/业务组的结果、连续轨迹和完整逐点明细，以及实际用量/延迟。已有单调性和 repeats 统计继续复用；诊断指标只在有对应标注/观测时计算，缺数据不造分母。

矩阵回放直接给共享判定函数传入少量明确的候选表/参数，默认逐格等同现行 100 格，保留 A1、A10、单调性和 ask/no-ask 契约校验。参考行为不由被测矩阵反推，N0 与矩阵分别记录。不建设通用策略语言、自动阈值搜索或生产矩阵编辑 UI。

MD/HTML/JSON 共用同一结果。MD 覆盖全部计划记录，必要时按组拆附录；HTML 在现有页面上增加轻量搜索/筛选和原文展开，不引入前端应用框架。跨版本比较先做同点、同参考和可比配置的计数差异，不默认要求显著性检验或自动因果归因。

沿用 `--out` 生成报告，完整 MD 可直接输出到 Git 目录；不另建 `--git-out` 和发布打包系统。报告开头放被测 commit、实际配置和原始运行位置，Git 保存 MD 及必要明细，其余可作为运行附件。索引是一份简短的版本/运行链接表，不建独立“最新通过”状态机。

验收用少量可人工核对的正常、失败、未运行、争议和多来源参考记录检查核心计数、分类重叠、三格式一致、引用、可比范围、确定性和文本转义。离线报告/回放不请求模型；运行失败和质量未通过不因报告成功而消失。完整报告交付前完成，扩展浏览功能不阻塞首批 S2。

### CW-10 复杂数据制作与分批复核

按已确认规模制作约 300 根/1,500 个基础点，以完整 lineage 按 5:3:2 分组；保留 legacy-v1 单独回归。先完成 24 根约 120 点，其中四根先贯通流程；随后边制作、边标注、边用于允许范围内的 S2，约 600 点时检查覆盖和成本。

每根必需的是合理任务、事件轨迹和有判断价值的审查点；每个参考有简短理由及必要证据定位。复杂案例才补作者说明或详细可见性诊断，不要求逐事件状态账本、逐事实处理链或多份重复卡片。作者说明和标准答案均不进入 reviewer/盲标材料。

F01–F12 作为主要业务分组；P 机制可按需打标签，W/S 仅作选材目录。连续调用、人类回复后继续、父子委派、跨轮事实、长上下文及正常复杂操作均须有代表，按实际覆盖补缺，不以多个固定比例或所有交叉组合凑数。源轨迹可手工构造或程序生成，明确 synthetic/reconstructed/real；关键事实用实际工具样例校验即可，不要求每根都完整执行一遍。

人工复核与扩充同批推进，批次大小按阅读负担决定，不为每批增加审批关口。人工范围与机器参考正式用途按数据方案 §4.1 的待确认建议安排，试标用于核实耗时和共识质量；保留随机与定向复核的区别，去重计算人工量，模型参考不冒充人工金标。

验收检查结构、真实可见事实、参考来源和依据、同源不跨 split、重复/换皮、正反覆盖及实际点数。只给有假设的少量点加诊断视图；工程边界和重复采样不充当新独立样本。

### CW-13 S2 校准、资源控制与候选选择

S2 从首批可评的 dev 开始，按需要扩到 dev/calibration。先跑默认 A，结合评分/材料错误选择少量有根因假设的变体；矩阵取舍用保存的分数离线重放。候选比较保持样本、参考和相关参数可比，不能以其他 target 的成绩代替自身证据。

沿用现有有界运行器，计划中写清模型、范围、repeats、repair、并发、timeout 和总资源额度；dry-run 算请求上界。累计用量直接汇总所选 run 记录，记录间复用必须匹配实际输入/配置；不新增独立账务数据库或调度服务。分批串行调度时扣除已耗额度后再派发，并发或 repair 仍由现有运行上限约束，不因新建 run 重置总额度。独立标注成本另计，缺失费用保持未知。

C1–C4 全套消融、有限轮数对照、结构化工具提取、cold/warm 缓存研究和高级统计默认不进入首版必做范围；只有当前结果提出明确问题才补实验。checkpoint 开/关与 T/H 的小范围验证可使用少量代表点，不做全部参数交叉。

在看 holdout 成绩前，选定真实生产配置、目标模型、参考范围和少量必要验收线；记录于现有配置/计划和报告。各分类指标不必各设门槛。旧 S1 建议数字不自动成为正式标准，不能看完成绩再改门槛。

验收交付可解释的候选选择、完整结果及使用额度；修复后只补受影响验证。S2 不等待固定日期，也不负责关闭当前 #83。

### CW-16 最终评测与 milestone 验收，复用 #85

按选定的实际生产路径、参考和验收线运行 holdout，完成必要的宿主回归并交付默认完整报告。holdout 可以存 Git，是否支持独立评价取决于其是否参与过开发/选择；若据结果修复，保留原结果并说明后续用途，需要新的独立结论时再补新情境。

同一份报告说明工程完成情况、各目标质量通过/未通过/证据不足、成本和遗留问题，不再另建验收证据包。未达到必要条件不宣布质量通过；数据数量、跑完请求和生成报告也不等于通过。

#85 继续作为最终评测/验收 issue，不再分别建立独立终评与总验收任务。发布新 milestone 时再核对其当前归属和依赖，不依据规划快照自动操作 GitHub。

## 3. 验证与协作边界

数据接口由 CW-02 维护，输入/回放由 CW-07 维护，结果存储由 CW-18 维护，参考规则由 CW-04 维护，统计/报告由 CW-19 维护。共享代码通过小 PR 顺序接入即可，不另建立接口注册或多级交接制度。

工程任务运行适用 unit/integration/UI 检查和 `pnpm verify`；影响宿主、UI 接线或生命周期时运行隔离 DSH E2E。数据检查复用加载器、引用/时序检查和有针对性的人工复核；语义近似重复首先按来源/模板检查并抽检，不为此新增向量数据库或相似度平台。

当前 #2 仍由 dsh 收尾。接收其基线 commit、S1 修订报告、实际配置、已有测试与 #85 状态即可，直接链接现有交付，不要求重复出具整套交接报告。旧 C1–C4 等未做实验可列为可选遗留，不自动成为新 milestone 的验收阻塞。
