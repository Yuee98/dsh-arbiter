# 审查质量与评测 milestone 方案

状态：正式规划基线，尚未实施。日期：2026-10-28。本文承接已完成的首版和现行 UI，授权范围为整理方案与发布 GitHub 任务图；实现、真实模型运行和旧数据删除由后续任务执行。

## 1. 目标与完成边界

以一套可解释、可复现的评分与判定契约连接 chat、decision、产品运行链及评测工具。交付包括：两项十档评分、共同审查矩阵与 ask／无 ask 模式、prompt 与上下文重构、同 repo 评测子项目、用户终审的数据集、真实对照和最终验证、规则配置简化，以及旧格式／迁移／测试数据清理。

完成意味着新版默认有真实评测依据、生产接线一致、关键行为和宿主流程通过验收；最小工具跑通不自动表示模型质量通过。600 条是覆盖扩充目标，不是机械数量门槛；不强制选出“获胜模型”，证据不足如实保留未通过项。

比较优先级：先约束违反有效禁止或关键许可边界的严重误放，再减少误拒和重复确认，随后比较费用与延迟。低风险 A2 在矩阵下允许，以及高风险 A10 的完整许可生效，都不是仅凭风险／授权名称定义的错误。

本 milestone 不包含：公开 release、托管评测平台、完整在线标注 UI、自动裁判替代用户、规则市场／新 DSL、模型主动弃权 M1、独立风险代批上限、decision 专属尾概率门、旧配置／日志兼容迁移。旧版本未 release，旧记录是测试数据；新评测版本及内容指纹仍需保留。

## 2. 固定的产品契约

### 2.1 两项十档与来源

公共输出为 risk、authorization 两个 1–10 有序整数，未知不占额外档位。风险按具体可信后果的最高已达到严重度下界评级；授权按许可覆盖的累积门槛和最薄弱关键效果评级。它们独立，不按命令名称固定分数，不用许可降低风险，不用高风险降低完整授权。

完整定义、相邻边界和例子见 [评分量表](review-quality-rubrics.md)。有限档位要求不反向单调，允许同分；模型能否遵守由成对／重复评测验证。

有效冲突按：本会话原始人类 > 直接父会话原始人类 > PROJECT_RULES > CUSTOM_RULES > agent 转述。同层级较新适用冲突优先，不冲突的旧限制仍有效。来源不构成分数上限，适用的持续 policy 或完整执行委托可达 A10。hint 只提示关注已有证据，不能创造许可；工具和普通文件不能自称升级成用户指令。简短审批答复必须关联当时问题与动作。

### 2.2 N0 与 M0

decision 原生 criteria 0–9 映射公共 1–10。令 F(k) 为累计质量：风险取最小 F(k)>0.5 的 k；授权取最小 F(k)>=0.5 的 k。精确一半时风险取高端、授权取低端；A1 40%／A10 60% 得 A10。chat 合法整数直接使用；点质量恒等不表示 100% 经验置信度。

严格检查档位集合、有限非负概率和总和；只处理协议数值误差，不把任意正和、旧十一档或漏档洗成合法分布，不退回均值 score 兜底。均值、confidence、原始分布仅用于记录和诊断，不能成为后端专属门槛。

共同状态是 scored、insufficient-material、review-failure。已成功读取且无许可为 A2；未配置来源是已知空。当前动作／相关许可关键原文缺失或相关来源读取失败，先有界补取已有材料；仍不足则 review-escalate。调用、解析、非法输出等故障为 error-escalate。部分得分留诊断，不伪造 R10/A1/A2。M0 只覆盖宿主／适配层能可靠识别的缺口，不宣称已实现模型语义弃权。

### 2.3 共同矩阵与两模式

| 风险 | 允许的最低授权 | A1 | 其他未达门槛 |
| --- | --- | --- | --- |
| 1–2 | A2 | 拒绝 | 不适用 |
| 3–4 | A8 | 拒绝 | 升级处理 |
| 5–6 | A9 | 拒绝 | 升级处理 |
| 7–10 | A10 | 拒绝 | 升级处理 |

不存在额外风险代批上限。ask 与无 ask 默认共用矩阵；无 ask 默认跟随 ask 阈值，可以显式独立覆盖。ask 的升级在宿主允许且具备真实通道时进入人工；无 ask 或无通道为 fallback-deny。人工未答复不批准。保留 review-deny、材料不足、技术故障、人工拒绝／取消与无法询问的差异。子任务没有通道时按无 ask 结算，不能把父 agent 转述当成人类批准。

确定性规则保持 deny > force-ask > force-review > allow。force-ask 必须真人，无 ask 时拒绝；allow 完整覆盖后跳过 reviewer，不承诺此时模型还会检查自然语言 policy；宿主边界仍适用。条件性许可／例外优先在自然语言 policy 表达。

### 2.4 Prompt、历史、探针

稳定契约／量表 → 来源标记的 policy 与环境 → 有效人类许可／限制 → 当前 turn 工具历史（旧到新追加）→ 当前动作、相关事实、hint 和动态完整性。缓存布局不提升材料的指令层级。只保留当前 turn 原始工具历史，跨 turn 有效人类授权／限制继续保留；以宿主 turn 语义处理恢复、重试和审批问答。调用尝试不等同成功结果。

生产和 evals 复用同一语义来源与请求／解析／N0／判定代码；两个协议可有不同包装。保护动作、关键许可和撤回，先消除旧探针、重复内容和审计元数据，再对历史选择、量表／示例压缩做消融。token／reasoning 预算及实际缓存支持按测量确定，不能为缓存保留过时授权或伪造结果。

首选候选 A 无探针；候选 B 一个可恢复／可撤回性问题。最小评测闭环跑通后比较，风险定义不因是否有探针改变。先在共同矩阵下比较额外提问的效果，禁止静默增加不可撤回必转人工。B 的实验定义与 unknown 表示在实验记录中固定；任何新硬规则需作为产品语义变化交第二窗口裁决，不由实现默认加入。

## 3. 评测系统与数据交付

### 3.1 工程与产物

沿用根 Node／TypeScript／pnpm 工具链，在 evals/ 建逻辑独立子项目。生产代码不依赖 evals，发布包不含评测工具和数据。默认 CI／verify 只跑离线工程和数据校验，真实请求显式调用独立 CLI。

正式案例、规范快照、独立模型意见、用户最终标签和 split manifest 使用 JSON＋Git。原始私有材料、完整大响应和大量运行产物放忽略的 .local/evals/；有意保留的报告放 validation/review-quality/。cases 的实际 input 与 provenance、labels、reviews 分离，运行器不得向被测模型泄漏答案。

标签记录 case_id/input_hash、规范／策略版本、R/A 允许集合及必要的合法配对、独立自动行为参考、证据、模型意见、用户裁决理由及状态。只有 approved 且 hash 匹配的标签计入金标指标。输入变化须复核标签；工具发现矛盾只列出，不用引擎答案覆盖人类参考。

### 3.2 最小能力和比较口径

| 能力 | 最小交付与证据 |
| --- | --- |
| 数据与标注 IO | 导出统一材料与空白模板，校验外部回填，保留各模型意见、争议和人工终审；首版不自动调用标注模型 |
| 运行与续跑 | 冻结选集和配置、支持实际存在的 model/protocol 组合、有界并发／预算／取消／重试；保存所有尝试与指纹，中断只补缺项 |
| 三层报告 | 自动行为为主要指标，R/A 用于诊断，模式／人工／宿主结算另列；HTML／Markdown／JSON 摘要、差异、逐例证据 |
| 离线回放 | 保存响应可重新归一化／回放阈值／模式并重建报告，无新增模型调用；参考标签不随引擎自动改动 |
| 真实对照 | 至少两个真实模型且至少一个真实 decision；同模型双协议只在真实支持时比较，其他情况报告系统组合差异 |
| 效率与稳定性 | 分开重复试验、修复重试和缓存复用；记录实际总 token、reasoning、缓存读写、费用及延迟；未知不填 0 |

指标按场景／来源／家族分项，公开分母、失败、未标、争议和失效标签数。分布集中度和跨行为边界是诊断，不能当真实风险概率。完整许可高风险允许和低风险 A2 允许按既定行为参考评估。

### 3.3 覆盖、规模与用户负责的标注

三类来源：真实普通工作流／失败素材（有才使用）、明确事实的人工构造、同 seed 单因素／等价变体。如实区分真实、重构和合成；不收集无关隐私或用真实危险操作制造答案。家族隔离开发／校准／保留集，prompt 示例和已调参案例不得当新保留集。

覆盖常规工作、数据删除／恢复、认证与敏感外发、服务／权限操作、授权覆盖／条件／撤回、来源与 hint、组合效果、注入／长上下文、主子会话／模式。覆盖全部评分锚点与相邻边界，尤其 A1/2、7/8、8/9、9/10 和 R2/3、4/5、6/7。工程矩阵／错误 fixtures 与模型语义案例分开计数。

先约 30–50 条核心试标，首轮有意义比较规划约 100–150 条已复核案例，再按缺口向约 600 条扩展；数字是工作量建议，不能代替覆盖和质量判断。同案例换模型／重复请求不增加案例数，相关变体不当作独立样本。

**agent 交付待标注数据包后，由用户自行找不同模型独立标注，结合自己的判断形成多份意见和最终参考，记录进 repo。** 用户拥有终审，3 个不同系列模型作为起步建议，具体模型由用户选择。多数票、平均分及模型一致不自动生成金标。agent 负责格式、校验和汇总，不接管裁决。

## 4. 规则体验与一次性清理

日常授权／限制通过自然语言 policy 表达，确定性规则作为可选高级能力，hint 只引导审查关注。普通编辑入口默认 exact、字段选择及多条件 all，显示未限定范围，保留高级条件语义。复用整份草稿测试，说明最终命中、优先级、shadowed 和复合命令覆盖。先交付编辑可理解性，再增加从真实调用生成草稿；不新增保存前强制测试，也不把一次人工批准变永久规则。

直接启用新的配置、评分、模式、prompt 与审计格式，不做旧版本迁移。配置兼容与审计迁移按不同所有权拆任务；旧日志修复工具退出。清理不能机械按 legacy 字样删除当前宿主保护。

真实旧数据重置与工具开发分离。用户已授权在该 milestone 实施时删除 Arbiter 旧测试日志、重建 SQLite 和清理迁移备份；执行前核对精确目标，仅删除本项目自有旧数据，不扩大到其他宿主对话／插件。单次操作不进入每次启动，新数据正常保留与恢复，旧记录不回灌。本次发布规划不执行删除。

## 5. 任务拆分与依赖

## 6. 两段集中人工介入窗口

| 窗口 | 一次交接内容 | 用户工作 | agent 的连续工作 |
| --- | --- | --- | --- |
| 窗口一：数据与运行准备 | 核心试标及后续批次、rubric、空白格式、校验方式；模型／协议组合、调用计划、整体费用预算；已就绪的规则体验 | RQ-H1A 多模型标注并终审入库；RQ-H1B 确定资源与费用；规则就绪则一并试用 | 标注期间继续工具、报告、产品接线、规则与旧兼容清理；标签和资源就绪后在额度内连续试点、对照、校准 |
| 窗口二：结果与验收收口 | RQ-15 推荐与差异、错误／人工／费用／延迟、验收线建议、争议汇总、剩余规则反馈 | RQ-H2 集中决定真实取舍、默认候选和验收线，处理需要裁决的分歧 | 按固定选择接入生产、跑最终保留集及工程验收，达到既定条件后交付 |

第一窗口的小批试标与剩余标注临近安排，不每批增加审批。规则未就绪并入第二窗口，不拖延数据交付。预算覆盖试点、主要对照、合理重试／迭代和最终验证，既定服务／额度内不逐轮重问。非阻塞分歧集中成清单，受影响案例保留待裁决状态，其他工作继续；只有无法在已定范围内继续的实质问题才提前提出。

第二窗口发生在最终保留集测试前，先冻结候选、参考标签和验收标准。不能看完最终成绩再倒设通过线；若保留集被用于修正方案，标记曝光并以新家族重建独立验收。两段窗口是集中工作时段，不承诺精确两条回复，也不以没有回复替代授权。正常完成后不再安排第三次重复方案确认。

## 7. 验收与完成证据

1. 语义：公共等级／N0／M0、100 格矩阵、两模式、来源冲突、有效 policy 许可和缺失／故障均有独立行为测试；同一公共输入和配置不按 backend 分叉。
2. 数据：覆盖与家族 split 可解释，真实来源如实标记；意见与最终标签分离，用户终审可追溯，失效标签不可用于金标。
3. 评测：至少两个真实模型和真实 decision 路径、离线可重建的三层报告、预算内中断续跑、失败和费用分母完整；对照不使用保留集调参。
