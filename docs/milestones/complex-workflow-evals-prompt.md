# Prompt 结构与参数说明

状态：2026-10-31 已确认设计的汇总，服务于下一 milestone，尚未接入生产。本文是 prompt 来源、选材、时间线和预算的详细规范；[主方案](complex-workflow-evals.md)只保留摘要，日志存储细则以其 §2.5 为准，避免重复维护。当前实现核对位置为本地 `8d0d2c9`。6,000/10,000 token 与单条 10% 是首批试标起点，最终默认值在候选确定时确认。

Prompt 长度控制只有整体预算和单条配额两层：整体为可配置的常态目标与硬上限；普通工具单元和辅助文本的单条配额由常态目标推导。不设工具类别总预算，不再使用旧 3,000 token 工具池、25% 分配或少量调用放宽规则。人类 20 条、父人类 5 条、历史 40 条的数量门槛已从新方案取消，默认也不设固定“最近 N 轮”门槛；读取和本地材料缓存另有工程保护。

## 1. 两种协议的包装

材料由同一个选择器产生，再用各协议包装。时间线中的 user/assistant/tool 是带来源的原事件，不因为展示在 reviewer 的 user payload 内就获得新的权限。

| 协议 | 外层结构 | 评分约定 |
| --- | --- | --- |
| chat | `system` 放固定契约、R/A 量表和回答格式；`user` 放下面的全部动态材料 | 返回仅含 risk、authorization 两个字段的 JSON 对象，两项均为 1..10 的整数 |
| decision | `state` 放固定契约、编号说明和同一份动态材料；`questions` 放 risk/authorization 两个 score 问题 | 各有 10 个 criteria，原生索引为 0..9，对应公开档位 1..10；由既有解析/N0 路径处理回答 |

无探针 A 沿用。公共行为矩阵和阈值由引擎结算，不发送给模型作为答案依据。input 预算不包含 output 生成额度；当前 chat 的 `maxTokens` 是另一个输出参数，不能与 `context.maxInputTokens` 混用。

## 2. 全局参数

| 项目 | 值或规则 | 状态与计量 |
| --- | --- | --- |
| 常态目标 T | `context.targetInputTokens = 6,000` | 新增可配置字段，估算完整输入 token；普通材料到此停止 |
| 硬上限 H | `context.maxInputTokens = 10,000` | 沿用既有字段，估算完整输入 token；指定基础材料可以使用 T 到 H 的余量 |
| 配置校验 | T、H 均为正整数，`T <= H` | 允许相等；显式非法值在 UI/API/schema 一致拒绝 |
| 旧配置补齐 | 缺少 T 时取 `min(6,000, H)` | 不扩大旧硬上限，不静默修正显式非法值 |
| 普通单条配额 C | `min(R, floor(T × 10%))` | R 为该次选择时的常态剩余额度；不另加单条配置项 |
| 默认 C 的上界 | 600 个估算 token | T=6,000 时；R 不足则更少，R=0 时不送；不是预留额度 |
| 工具总 token 上限 | 无独立值 | 工具合计与其他普通材料共同受常态目标约束 |
| 人类、父人类、工具与裁决数量 | 无独立 prompt 条数上限 | 取消 20／5／40，不在候选提取阶段提前执行；按来源/可见截止点、保位与剩余 token 选择 |
| 跨轮范围 | 默认不设固定最近 N 轮门槛 | 已确认；既定来源和消息类型内由近到远选取，当前轮/有限轮数仅保留为旧基线或评测对照 |
| 普通 assistant 候选数 | 最多 1 条 | 本会话最新人类消息前最近一条可见回复；明确绑定的问题另走问答规则 |
| checkpoint 默认候选数 | 最多 1 条 | 仅最新一条；允许对照不送，低优先级 |

单条配额包含该单元的正文、参数、状态、来源和包装，不给 stdout、stderr、多个内容块或参数/结果分别分配 C。明确绑定的受保护问题即使由 assistant 提出，也按原文保位，不套普通 assistant 配额。其他人类原文、父 agent 的 user 转述和结构化先前裁决按完整消息/记录取舍；当前动作与规则按基础输入规则处理。结构化派生事实按可分离记录裁剪，不额外虚构一个固定单条百分比。

普通 assistant 的最多一个相邻候选、checkpoint 的仅最新一条是内容选择规则；最新本会话/父会话人类原文的保位是最低保障。这些规则继续保留，不属于取消的数量门槛。读取扫描量和缓存容量是独立内部资源参数，数值由 CW-07 校准，不直接继承旧条数字段，详见第 6 节。

不新增最近 N 轮设置，较早事件不会仅因跨过轮次边界就失去候选资格。先识别保位和明确绑定，普通历史按机械优先级、同优先级内按各自宿主序号由近到远选择，最后按各会话原序展示；父子会话不按墙钟混排。没有固定轮数不等于发送全历史，长会话更常接近 T 的成本与质量取舍进入评测。

## 3. 逻辑结构与逐项字段

下面使用逻辑分块名说明新方案，其中父人类证据区与本会话时间线是新组织方式，不代表已有 wire 字段已经重命名。保持当前大体阅读顺序；动态环境字段后移等缓存布局实验留待有性能证据时再做。

```text
固定契约与量表/回答定义
动态材料
  1. 项目规则与全局规则
  2. 环境与请求归属
  3. 父会话人类证据
  4. 本会话统一时间线
       人类原文 / 父 agent 的 user 转述
       选中的普通 assistant 回复
       工具调用及结果
       最新 checkpoint（若选中）
  5. 先前裁决
  6. 当前待审动作
  7. 当前动作派生事实
  8. review hint（若有）
  9. 必要的材料完整性说明
```

### 固定契约与量表

- 内容：reviewer 只评估一个待审动作的 risk 与 authorization；R/A 独立，按后果和有效许可判断；每项 10 档，源文本来自共享契约和 rubric。
- 来源冲突顺序：本会话原始人类 > 直接父会话原始人类 > 项目规则 > 全局规则 > agent 转述。冲突优先级不构成评分上限；父人类原文仍能支持完整授权。
- 同层较新内容只在适用冲突点覆盖旧内容。构建器不据此判断哪条许可有效，仅传递原文、来源与顺序。
- 预算：属于基础输入，可以使请求超过 T；不按普通单条 C 截断。固定契约与必要协议内容无法在 H 内容纳时，不能发送被悄悄改写的契约。

### 1. 项目规则与全局规则

| 项目 | 来源与值 | 选择及预算 |
| --- | --- | --- |
| `PROJECT_RULES` | `context.projectRules` 控制读取；现行默认启用，候选文件顺序为 `.dsh/arbiter.md`、`.arbiter.md` | 读取第一个存在的候选，读取失败与不存在分开；属于基础输入 |
| `CUSTOM_RULES` | `context.customRules`，现行默认空字符串 | 用户全局偏好，属于基础输入；不升级为 system 契约 |
| 来源元数据 | 启用、存在、路径、可读性、实际送达内容及裁剪记录 | 必要状态须真实；新格式不把旧 `limit: 2000` 等元数据冒充仍有效限额 |

取消两类各 2,000 字符和合计 3,000 字符的前置截断。允许使用 T 到 H 的余量，达到 H 时由统一预算按固定规则裁剪或省略，并记录缺失；不是无限量必带原文，也不套普通辅助文本的 C。

### 2. 环境与请求归属

当前环境字段包括 `cwd`、`tool`、`session_kind`、`turn`、`config_revision`：cwd 是实际工作目录，tool 是当前工具名，session_kind 为 main/subagent，turn 使用宿主轮次或 null，config_revision 为实际配置指纹。事件另带所属 session、原消息/调用标识，防止父子或兄弟混用。

这些值按本次请求实际来源填入，不从标准答案或案例文件名构造。必要环境和来源标记属于基础输入，无专属固定 token 数；null 表示未知，不转成轮次 0。新事件身份字段由 CW-02 定义，不能声称当前 `ContextToolCall` 已拥有所有新字段。

### 3. 父会话人类证据

- 来源：直接父会话中宿主识别的人类原文和真实问答答复。保留父 session、原事件 ID、原序号、可知时间、轮次及实际读取截止点。
- 角色与证据：来源为 parent-human，原文支持 explicit 证据；是否授权当前动作由 reviewer 判断。parent authorization 的存在标记只表示存在原文，不表示已批准本次动作。
- 顺序：父证据区内部按父会话原序；不按墙钟混入子会话事件，不复制全部父工具记录，也不读取兄弟会话补齐。
- 数量与轮次：新方案取消 `parentHumanItems=5` 的最大条数限制，也不设固定最近 N 轮；最新父人类原文在存在时保位，较早消息在实际可见截止点前按机械顺序与常态剩余预算选择。
- 预算：最新原文及明确绑定问题可使用 T 到 H 的余量，不套 C；较早消息只竞争常态额度，优先整条取舍。取消原文 4,000 字符的前置截断。
- 缺失：没有父会话时不构造占位证据、不占额度；应读取但不可读、确实没有人类消息、读取保护导致未完整扫描、预算停止补读或省略分别记录。截止点后的父消息不进入较早视图。checkpoint 不能弥补不可读的人类来源，缓存 miss 也不证明没有父人类消息。

每次审查按当前截止点重新选择父人类材料，不能为了缓存永久固定旧副本。父工具、兄弟会话或继承 seed 不自动作为本会话历史；按原事件 ID 去重，文字相似不等于同一来源。

### 4. 本会话统一时间线

所有选中事件按本会话宿主序号展示，保位不会移动事件位置。事件记录来源、角色、轮次、关联 ID 及实际可见顺序；相邻不表示明确问答绑定。省略区间明确标记，未知数量不能编造。

| 事件类型 | 候选与来源 | 单条处理 | 可使输入超过 T |
| --- | --- | --- | --- |
| 最新本会话人类原文 | 宿主识别的人类输入，包括真实 ask 答复；存在时保位 | 原文及明确绑定的问题完整保留，不套 C | 是 |
| 较早人类原文 | 在既定来源和可见截止点前按机械规则选择，不设最近 N 轮门槛 | 优先整条保留或省略；无前置字符截断 | 否 |
| 父 agent 的 user 委派/转述 | 按进入本会话的真实位置展示，来源为 relay，不因 user 角色变成人类 | 作为委派上下文按消息选择，不属于“只选一条 assistant”的过滤范围 | 否 |
| 普通 assistant 可见回复 | 最新本会话人类消息前最近一条，最多 1 条；没有本会话原始人类消息则无此候选 | 低于人类证据和近期原始工具记录，不保位；最多 C，长正文取头尾并标记 | 否 |
| 历史工具调用及结果 | 真实调用与可观测结果，排除当前待审调用；通过 call ID 关联 | 一次调用整体最多 C，多通道共享，少量调用也不放宽 | 否 |
| checkpoint | 最新可读的 compact-checkpoint，默认最多 1 条 | 低优先级、不保位、最多 C；预算紧张先省略 | 否 |

普通 assistant 仅提供相邻上下文，不能据其内容自动绑定人类“可以”。宿主明确绑定的问题独立遵守问答/保位规则，不受普通回复的候选数或 C 限制；同一原事件只展示一份正文，引用保留来源。

工具材料应包含：工具名、参数、工作目录或其可追溯环境、session/turn、事件序号、call/result 标识、观测时间、状态、结果正文、通道及省略记录。成功、失败、未观测到结果分开；exit code 仅在宿主确实提供时记录。调用和结果可以出现在不同位置，晚到结果不回填到调用发生时刻；未观测结果不伪装为成功或失败。

2026-10-31 已确认首版结果类型：处理文本和可序列化结构化结果；图片、音频及附件仅保留实际可得的类型、引用和未提供正文说明，多模态判断后续另做。不新增附件下载、OCR、转写，也不将 JSON 中的二进制/base64 媒体伪装成普通文本绕过范围；混合结果中的可用文本按其实际来源处理。类型与引用同样遵守共同脱敏、来源标记和预算。

工具正文完成共同脱敏后才参与选取。一次调用的参数、结果及包装合计受 C 约束，参数和结果不分别享有一个 C。先保留可辨认的调用信息，再分配正文；参数片段不表现为完整命令，不完整 JSON 不表现为完整对象。没有独立工具总额；在常态预算和读取保护允许时可以继续考虑较早调用，不在第 N 轮处提前停止。预算无法继续纳入、没有更多可用材料或触及读取保护时结束，不强行填满 T。

正文需裁剪时按可用额度保留头尾各半，尽量对齐完整行或内容块，中间标出省略；对齐不能突破上限，超长单行保持有效文本。预算竞争时先省略低优先级 checkpoint、缩短长工具结果，再按确定顺序淘汰较早非保位事件或明确绑定单元。结果保留时必须仍能辨认所属调用，晚到结果不挪回调用时刻。

checkpoint 是有损摘要，不是原始人类许可或实际执行证据。摘要中的“用户已批准”仍只是摘要内容；它被省略不抹掉“发生过压缩”等已知来源状态。

### 5. 先前裁决

内容来自同会话的实际审计/宿主历史，包括 `callId`、时间、工具、配置指纹、trace/result，以及可取得的 reason、ruleId、阶段链和来源冲突。`coverage` 区分 known-empty、complete、partial、unknown；`truncated` 另说明容量删减，两者不能互相代替。

这部分属于常态补充材料，无保位或单独 token 预算，优先按完整记录选择/省略；不将阶段链截成另一个貌似完整的结论。新方案取消工具与裁决合用的 `historyMaxItems=40` 送审门槛，也不改成两类各 40 条。现有裁决缓存与恢复读取对同一配置的依赖需一并拆开，避免最终选择器仍只拿到被前置条数限制删减的记录。旧拒绝、技术失败或单次中止不自动成为新的持续人类禁止。

### 6. 当前待审动作

字段包括工具 `name`、实际 `arguments`、适用时的 `programText` 和已有截断记录。它尚未执行，不附未来结果，不作为历史工具单元重复计数。

当前动作属于基础输入，可以使用 T 到 H 的余量，不套历史工具的 C。尽量完整；只有硬预算仍不满足时最后裁剪，并保留原始/可见材料和裁剪区间。`arguments` 与 `programText` 若重复承载同一程序，需要同步处理，不能通过第二份正文绕过预算。送审副本的裁剪不改变实际工具执行参数。

### 7. 当前动作派生事实

现有 `ACTION_FACTS` 包括解析成功/失败和语句数，观测到的写入、网络命令、凭据路径、管道执行、替换/子 shell 数量，以及 opaque、未解析展开、完整性、父证据存在、与既往拒绝效果重叠等标记。它们来自解析器和实际历史处理，不是模型生成的金标或预先给定的风险评分。

派生事实属于常态辅助材料，无独立总额；按结构化可分离记录缩减或省略，保持可读结构及完整性标记，不新设单条 10% 规则。没有可解析事实时如实表达，不把 parse error 当成人类未授权。必要的来源/缺口说明仍进入完整性报告。

### 8. Review hint

当前 `REVIEW_HINT` 是本次请求已有的可选 hint 字符串，通常来自命中的规则。它只能帮助解释已有材料，不独立提供事实或授权。

最多一个现有 hint 字段，不存在时不生成。作为普通辅助文本，不保位、不预留额度、最多 C，也不能使输入超过 T；新选择器需要明确裁剪或省略路径，不沿用旧实现中未单独裁剪 hint 的遗漏。

### 9. 必要的材料完整性说明与运行诊断

reviewer 只接收影响判断的来源、缺失、截断和阻断说明；T/H 运算、扫描量、缓存统计和细粒度选材记录留在运行日志。复用构建器已有结果，不为每条事实建立全链路追踪系统。下面区分记录目的，避免把工程诊断全部塞进 prompt。

| 内容 | 值及含义 |
| --- | --- |
| `status` | complete / incomplete / insufficient；由实际来源和裁剪结果计算 |
| `blocking_gaps` | 共享契约识别的阻断缺口；普通裁剪不能自行增加一个阻断结论 |
| 来源/缺失说明 | 已知空、不可读/已清理、读取保护导致未完整扫描、上游截断、日志采集截断、来源/截止点排除、预算停止补读及已读材料的 token 省略分别记录；有限轮数对照单独标记窗口排除 |
| 读取与缓存覆盖 | 运行记录保存截止点、可知覆盖、停止原因；prompt 只说明因此不可用的材料，未知总数不编造 |
| 输入预算 | 运行记录保存 T、H、最终估算 token 和超过目标的原因，不要求发送这些计算过程 |
| 选择与省略 | prompt 标出必要省略及来源；具体保位/选材/裁剪诊断按需保存在运行记录 |
| 当前动作裁剪 | prompt 明确哪些内容不完整；长度和精确区间在运行记录中可查，不恢复字符硬上限 |

必要完整性说明属于基础输入，不允许为了压缩长度隐藏缺口；这些说明写入后仍须复核完整输入长度。普通截断不自动变成人工审批或拒绝。受保护原文最终无法装入时，沿用既有保位缺口或 OVER_BUDGET 准备失败路径。

## 4. 构建顺序与数值示例

先固定本次来源与事件截止点，优先取得保位原文及明确绑定的问题，再通过有界读取/缓存补读建立带来源和序号的候选。提取阶段不再执行 20／5／40 数量限制或最近 N 轮筛选。基础输入包含固定契约、必要环境/元数据、两类最新人类原文及问题、当前动作、项目/全局规则；普通历史、先前裁决、派生事实、hint 和 checkpoint 不属于这份基础输入。

设基础输入完整渲染长度为 B：

| 条件 | 行为 |
| --- | --- |
| `B <= T` | 在既定来源/类型和截止点内按机械优先级由近到远补普通材料，较早轮次也可入选；适用单条受 C 约束，最终不超过 T，读取保护仍生效，不强求填满 |
| `T < B <= H` | 只发送基础输入，不补普通历史；记录超过目标的原因 |
| `B > H` | 降级可裁剪规则材料，最后裁剪动作；保护原文不动。仍不满足则准备失败；不回填普通历史 |

T=6,000、H=10,000 时，基础输入为 2,000、工具候选足够且没有其他补充材料，工具合计可占用接近剩余 4,000，单次调用仍最多约 600；只有两次工具调用时不因条数少就提高每次上限。基础输入为 7,200 时，不再添加普通工具历史。保护人类原文有 2,000 token 时不被压到 600；普通 assistant 回复有 2,000 token 时最多取约 600 或更少。这些示例中的余量均须含包装重新核算。

最后按父/本会话各自原序渲染，保位不改变位置。两协议共用选材，按完整渲染估算较大者检查；修复重试的新增提示也计入该次请求。缓存命中与否不改变 T/H/C，也不允许发送超预算材料。

## 5. 当前实现与新方案的差异

核对来源：[默认配置](../../src/config/defaults.ts)、[证据提取](../../src/snapshot/evidence.ts)、[规则读取](../../src/snapshot/guidance.ts)、[当前分块渲染](../../src/reviewer/material.ts)、[协议包装](../../src/reviewer/prompt.ts)、[历史计数](../../src/snapshot.ts)、[裁决缓存与恢复](../../src/host/history.ts)。下列代码值仅是现状，不自动成为新方案的最终参数。

| 项目 | 当前实现 | 新方案 |
| --- | --- | --- |
| 输入长度 | 只有 `maxInputTokens=10,000` | 新增可配置 T，初始 6,000；保留可配置 H，初始 10,000 |
| 人类证据条数 | `evidenceMaxItems=20`，合并不同来源的证据 | 取消最大条数；保位之外的消息按机械顺序与 token 预算取舍 |
| 父人类窗口 | `parentHumanItems=5`、`parentEvidenceFloor=1` | 取消五条上限；最新父人类原文保位，较早消息竞争常态额度 |
| 工具与裁决条数 | `historyMaxItems=40` 共同限制，也用于缓存/恢复 | 取消送审四十条上限；独立定义读取保护与缓存容量，不从旧值自动映射 |
| 工具范围和结果 | 当前 turn；参数与成功状态，无结果正文 | 不设固定最近 N 轮；可取得的历史结果按统一预算选取，读取/缓存保护独立 |
| 人类/规则/工具的字符截断 | evidence 4,000；问题/checkpoint 2,000；规则各 2,000、合计 3,000；历史参数默认 200 | 取消 prompt 前置字符硬截断，由统一预算构建器处理 |
| 普通 assistant | 不作为独立时间线候选；现有部分短答会带问题上下文 | 最新人类前最近一条普通回复候选；明确宿主绑定的问题单独处理 |
| checkpoint | `checkpointMaxItems=3`，独立数组 | 新默认最多最新一条，时间线原位、低优先级、最多 C |
| 授权与历史布局 | HUMAN_AUTHORIZATION 与 TURN_TOOL_HISTORY 分块 | 父人类证据区＋本会话统一时间线，保留来源语义 |

输入范围、顺序、字段或预算行为变化由 Git commit 与实际配置追溯，运行保留真实送审材料，旧运行继续按原内容解释；不另维护投影/渲染 hash 或版本号。旧 `evidenceMaxItems`、`parentHumanItems`、`historyMaxItems` 从新版 prompt 设置移除，升级说明明确其停用及生效版本；旧显式值不得继续在候选阶段生效，也不自动映射为内部保护值。仍待细化/校准的是确定性选材顺序、独立读取/缓存保护和最终 T/H/C；20／5／40 和固定最近 N 轮不再是待定默认参数。有限轮数只用于明确命名的评测对照，不静默恢复为生产默认。现有宿主 `config_revision` 和历史记录按原义读取，评测不在其上叠加另一套身份体系。

## 6. 不属于 prompt token 限制的值

| 层次 | 独立保护 | 约束 |
| --- | --- | --- |
| 来源读取 | 扫描事件数、读取字节量与异常超时；具体值待 CW-07 校准 | 尽量索引、分页、增量读取，不每次无界扫描全会话；不将旧 20／5／40 改名后继续当作选材门槛 |
| 本地材料缓存 | 单会话及总体内存容量、淘汰与补读规则；具体值待 CW-07 校准 | 淘汰副本不删除源日志；miss 后按需补读，无法补齐就记录来源状态 |
| 日志保存 | 单次调用采集上限、转文件阈值和统一 retention | 独立于读取、缓存和 prompt 预算，已有确认值继续生效 |

本节的本地材料缓存与 provider 前缀缓存不同。相同来源可用性、截止点和读取契约下，已有缓存与冷恢复应给出一致的候选材料及完整性声明。分页和补读不得引入截止点之后的事件；保位项和明确绑定的问题优先定位，不等待普通扫描恰好命中。宿主只支持全量快照时，需说明接口限制并提供可行的有界处理方案，不能把复制全部历史后再切片称为有界读取。

实现先复用现有读取和缓存；只为实际接口限制或实测瓶颈增加必要的索引、分页或增量优化，不要求所有方案都建，也不增加新的面向用户的缓存/读取调参面板。有界处理、保位及真实缺失说明仍是必需行为。

无固定轮数门槛时，补读依旧受工程保护；旧事件可以按预算入选，不要求先把全部会话装进内存。源 retention 和既有会话/重置契约继续约束可用材料，不恢复已清理或被原契约隔离的记录。轮次仍是来源元数据，不代替对象事实或授权有效性的判断。

触及读取保护时记录实际覆盖、停止原因和可知计数，区分“未完整读取”与“已读取但因 token 预算省略”；不能宣称剩余历史为空或完整，也不能伪造遗漏条数。读取策略由被测 commit 与实际保护参数定位，实际覆盖进入有效视图。保护原文最终取不到时按既有缺口契约处理；普通材料受限不自行变成 M0/人工询问/拒绝。工程保护不能因提高 T/H 被绕过，日志也不因缩小 T/H 或缓存淘汰而删减。

日志按脱敏后、未压缩 UTF-8 正文字节计量：单次工具调用结果合计最多 1 MiB，超过 64 KiB 转文件；超采集上限保留头尾各约 512 KiB 并记录。SQLite 和文件沿用统一 retention，现行默认 30 天/1 GiB。内部扫描事件数、轮次、时间和存储容量继续使用各自单位。

这些日志限制不会因 T/H 调整而改变，日志保存的较充分正文也不会自动全部送入 prompt。取消 prompt 字符上限不代表无限采集、永久保留，或能够恢复宿主已经省略的内容。
