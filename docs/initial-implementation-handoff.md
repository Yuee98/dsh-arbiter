## 交付目标

用户能够在隔离 DSH profile 中安装并启用插件，选择 reviewer 和审批模式，创建和测试规则，运行主／子任务，查看每次调用为什么被放行或拒绝，再从历史生成候选规则并人工确认添加。配置能够保存、生效、重新加载；记录能够查询、恢复、清理和识别版本。首轮以这个用户流程作为完成目标，按下文顺序持续实现，不在完成骨架或 mock 后停止。

仓库已有 TypeScript／Node 工程骨架和 CI，沿用现有工具链。DSH 0.2.1-rc.2 的七组宿主覆盖验证已经完成，先复用其结论、探针和原始证据，再补充正式插件集成验证。原 [P0–P11](implementation.md#design-12) 保留为早期路线，本轮顺序以本文为准。

<a id="contracts"></a>

## 实现中保持的契约

1. 规则优先级和阶段术语使用当前定义，`review(default)` 不是第五种可配置 verdict。已完整匹配的 allow 跳过插件 reviewer；插件放行不等于绕过宿主沙箱或其他 guard。
2. normal 同样自动审查。normal／strict 共用同一常规策略，区别是是否新发起插件人工审批；progress 在形成审查结论前调整条件，不覆盖已经形成的拒绝、故障或强制人工要求。子任务只提供 strict／progress。
3. 需要人工且无法发起时记录完整链并以 fallback-deny 结束当前调用；已发起人工但无决定地结束是 human-abort；仍在等待是 pending。审批模式不限制宿主可用的 ask。
4. chat／decision 统一授权标准。父会话人类原话可以支持明确授权，父 agent 的纯转述不能创造授权；历史批准、截断摘要、工具输出和项目文件各保留其来源。
5. 配置成功应用后用于后续未作出的判定；已形成结果继续推进，旧响应按原协议解释，已弹出的审批保留。不要额外加入每次执行前重审。
6. 正式规则只通过用户编辑或人工确认候选产生；取消 `source: learned` 的运行时特殊语义。实时批准当前调用不顺便创建永久规则。
7. 当前状态及有限历史由内存维护；会话记录与 SQLite 独立写入，恢复优先会话记录、SQLite 有界补缺。共同事件标识用于去重；来源冲突、丢失、未知不能变成许可。
8. 保存完整约定审查材料和每次实际模型调用的可见返回／错误，配置与模板按不可变内容去重。Reviewer 连接凭据不进入审计；日志失败使用有界队列、重试及聚合提示，不影响权限结论。
9. 审计默认 30 天／1 GiB，可在高级设置调整；按逻辑调用及引用清理。旧数据保留原意、版本化迁移，缺字段记未知；迁移失败保留原库，旧插件不覆盖较新数据库。
10. 覆盖说明依据已验证机制：直接 Node 效果不是独立工具门禁；MCP 服务端内部效果、外部后端子任务内部执行等不可见路径不能标成逐项已审查。

## 未决项的实施方式

允许选择一个明确、可测试、可调整的初版行为，记录为“初版实现选择”，不因显示名称、字段名、物理表结构或未校准参数反复等待确认。建议采用以下起点：

| 未决项 | 首轮实现起点 | 保留的边界 |
|---|---|---|
| 外层 `run_code`（C5） | 外层进入工具准入；未有明确规则结论时，按完整程序输入审查；内层工具照常独立处理 | 不用 bash 解析器处理 JS／TS，不以外层 allow 给全部内层调用授权；外层审查不声称拦截每个直接 Node 效果 |
| 非 bash 规则目标 | 使用显式工具名／命名空间及必要参数选择器，补充最小 schema，并在编辑器与测试器中解释匹配对象 | 不把任意 JSON 拼成 shell 文本匹配；不凭同名工具混淆不同 MCP server |
| 与其他审批者共存（O11，后续产品契约已确认） | 按[共存契约](architecture.md#approval-provider-coexistence)实现官方互斥、其他插件行为告警和运行中通知；保留原门禁与模式，不统一 force-ask，检测真实注册及恢复状态 | 不维护第三方名单；不承诺在所有宿主监听器之前运行，不修改宿主核心或自动移除用户日常 profile 的插件。通知与热更新需真实验证 |
| 初始模式及名称 | 2026-10-24 已确认主 normal、子 strict、guarded、chat + 跟随会话模型及空规则表；见[初始默认值](configuration-and-audit.md#initial-defaults) | 替代此前暂定默认值；显示名称及 tooltip 按模式专题，安装不自动接管会话，首版不附带预设命令规则 |
| 具体判定条件与阈值（C1–C4） | 基于现有判定引擎和 R1–R8 候选整理一份自洽、带版本的初始策略，写成可测试的规则与参数；列明解决了哪些旧稿冲突 | 不同时启用互相矛盾的旧规则；保持 normal＝strict、后端统一授权、progress 不扩大强制人工／故障放行。阈值标为未校准 |
| 不完整 AST／事实 | 显式保留 completeness 和 unresolved 状态，已识别的禁止或强制审查条件仍可参与判断；缺失节点不能视为已被 allow 覆盖 | 不把“没发现危险”当作证明完整安全；支持哪些 shell 结构必须有对应案例 |
| 项目自然语言规则（后续来源契约已确认） | 按[来源契约](review-context.md#authorization-source-priority)接通 projectRules.enabled，默认开启；每次新快照取得当前内容，已发出的请求不变。自由文本可表达持续授权，用户负责，不逐次认可 | 本会话人类 > 父会话人类 > 项目 > 全局指引 > 转述；同层相关冲突以较新适用指令为准。指引不直接修改命令规则或代码策略 |
| 高级设置、重试及等待参数 | 先开放已有明确 schema 的有限参数，提供默认值及自定义状态；按现有草案取可运行初值 | 不另造完整策略 DSL，不把任意超时解释为用户明确拒绝 |

执行者可以调整这些起点，但应说明涉及的未决编号、具体行为、选择理由、用户可见影响与验证结果。若发现必须扩大权限、把低可信内容升级为授权或宣称尚未取得的覆盖能力才能继续，应保留该分支的未完成状态并继续独立模块；普通工程取舍无需停工。

实现选择集中追加到[决策登记](decisions-and-questions.md)的独立小节，并从相应专题链接过去，避免另维护一份重复产品规范。已确认契约与实现选择冲突时修正实现，不能把用户决定降为建议。

| 顺序 | 工作 | 应得到的可运行结果 |
|---|---|---|
| A | 接续工程骨架，定义调用／阶段／策略／配置版本类型；规则解析与匹配；最小宿主适配和真实 chat 链路 | 隔离 DSH 中能运行一条真实调用，看到规则短路或模型审查后的真实门禁结果；确定性夹具覆盖拒绝分支 |

真实模型验证优先使用 DSH 已配置的 `chat.provider: session`。实现 decision 后端的请求、分布解析和故障处理；缺少可用 endpoint 或凭据时使用协议夹具验证，明确真实网络未测，不要求为完成本轮另行购买服务，不以 mock 冒充真实审查。

## 验收与交付

至少覆盖以下能发现产品偏差的测试：

- 规则优先级、复合命令部分覆盖、重定向／赋值／展开／解析错误；规则免审路径确实没有调用 reviewer。
- 相同信号与策略下 normal／strict 的审查结论一致；force-ask 在自动档不能被模型代批；progress 对比常规策略的扩展有明确条件。
- reviewer 合法批准／拒绝／升级、协议错误及修复尝试、超时；人工允许／拒绝／无决定结束；fallback-deny 后其他独立调用仍可继续。
- 配置变化发生在模型返回前后及人工等待期间；同内容去重、恢复旧配置、外部非法文件、UI 草稿冲突。
- 实际 body 未执行的拒绝证据、MCP 在 RPC 前被阻止、子任务身份、外层／内层关联；未运行真实人工 UI 就明确标注，不以模拟通过代替。
- SQLite／会话记录写入失败、恢复来源补缺及冲突、有限历史窗口、容量与时间清理、引用完整性、迁移失败与较新数据库保护。
- 离线候选在确认前不参与运行时；确认后通过普通配置校验，匹配范围与用户看到的一致；旧记录缺字段不会产生伪造的回放结论。
- 配置界面和日志详情使用真实服务与数据；保存失败、空记录、存储退化、无效规则有可理解的状态。具备 Web 环境时实际操作验证。

运行仓库现有 `mise exec -- pnpm verify`，并按改动补充真实 DSH 集成与界面检查。依赖、构建方式及包 exports 可以为实际插件需要调整，保留原有检查的作用；不通过取消检查或保留 dummy 测试冒充验收。

集成使用隔离的 DSH 数据目录、profile、测试文件及本地接收服务。保留现有未提交文档及 `validation/` 证据，新增运行证据另建目录。无需重复执行整个 1–47 总清单，只执行本轮实际实现与新增疑点相关的验证。

最终更新 README 的真实功能状态、本地安装和试用步骤，并提交一份实施报告：已实现流程、可运行入口、检查命令及结果、真实／模拟验证的区别、初版实现选择、仍需人工参与或外部服务验证的项目。产品语义未定与实现尚未完成分别列出。停用／卸载的初版行为应保留用户规则与日志，并准确说明宿主恢复行为；不自动清理日常配置或公开发布 npm。
